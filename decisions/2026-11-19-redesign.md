# 2026-11-19 · Redesign, security, platforms, learning

## D1 · What encryption protects
**Chosen:** the link and the record. Phone-to-computer traffic goes over HTTPS. The reading
record (reads, marks, threads) is encrypted on disk, with the key in the OS keychain. The reader's own files (`sections.md`, `interests.md`, `feeds.yaml`, `inbox.md`,
`outlets.json`, `paper.yaml`) stay plain and hand-editable.
**Not chosen:** link only (the record would stay readable from backups and syncs); everything
behind a passphrase (the morning run could not unlock it alone); hiding the record from Claude
(would need a local model and give up Claude as the writer).
**Accepted cost:** a one-time trust step on each phone; the record can no longer be read in a
text editor.
**Unchanged:** Claude reads the record each morning through `paper context`. Encryption does
not hide it from Claude.
**Revised by D16:** `threads.jsonl` turned out to hold only news; what the reader follows is in
`reads.jsonl`. The encrypted record is `reads.jsonl` and `marks.jsonl`.

## D2 · Platforms
**Chosen:** macOS, Windows and Linux desktops running the Claude app (Linux is in beta), plus
any phone through its browser.
**Not chosen:** Mac + Windows only; a second path without the Claude app (CLI or API key).
**Accepted cost:** three install paths and three background services (launchd, Task Scheduler,
systemd user unit) to maintain. A paid Claude plan is still required.
**Found since:** the Linux desktop app is beta for Debian and Ubuntu only; Fedora and Arch get
the CLI, which is the path not chosen. Scheduled tasks are not on Anthropic's list of features
missing on Linux.

## D3 · What the learner optimises
**Chosen:** finish and remember. A local per-topic model (Thompson sampling) counts finished,
kept, marked and a recalled card as good, and an open alone counts for little. A fixed share of
each issue stays exploration. FSRS fits its parameters to the reader's own reviews. News
sections stay ranked by k. Each steered piece says why it is there.
**Not chosen:** learning from opens (rewards headlines); personalising news (breaks "independent
outlets decide"); keeping the rules as they are.
**Accepted cost:** adapts more slowly than click learning; one more line on steered pieces.
**Open:** where the "why" line shows (D6).

## D4 · Look
**Chosen:** ink. Monochrome black on paper, taken from the pilcrow icon: heavier rules, section
heads at the pilcrow's weight, a mark shown as ¶ (highlight) or ? (question) in the margin
instead of a yellow or blue fill.
**Not chosen:** ink plus one red; keeping the current look and swapping only the marks.
**Accepted cost:** highlight and question are told apart by shape, not colour; the page is more
austere.

## D5 · How the phone gets HTTPS
**Chosen:** the paper's own certificate authority, made at setup and used for this paper only.
Pairing installs it on the phone once. On iPhone that means installing the profile, then
turning on full trust under Settings › General › About › Certificate Trust Settings.
**Not chosen:** Tailscale (needs a third-party account, though it would work away from home);
a self-made certificate that the phone warns about (teaches clicking through warnings).
**Accepted cost:** a few extra taps per phone, and still home Wi-Fi only. Android behaviour is
to be verified.

## D6 · Where "why this is here" shows
**Chosen:** at the top of the piece in the reader view, beside the thread box, with a
"less of this" control.
**Not chosen:** under the lead on the issue (one more label on the front page); only on
Settings (too far from the piece).
**Accepted cost:** the reason is visible only after opening, so it cannot help with the
decision to open.
**Consequence:** "less of this" is a new signal and has to be logged so the learner can read it.

## D7 · How we work on it together
**Chosen:** the live app in the in-app browser pane. Claude changes the real app; the reader
clicks through it and comments in chat.

## D8 · Order
**Chosen:** 1 ink design → 2 HTTPS and encrypted record → 3 Windows and Linux setup → 4 learner
and why line.
**Accepted cost:** the phone link stays unencrypted on Wi-Fi until step 2.

## D9 · Typeface
**Chosen:** one open-licence serif bundled with the paper and served from the reader's own
computer, never from a font service: Source Serif 4. Every OS and phone shows the same paper.
**Not chosen:** system fonts per OS (New York on Apple, Georgia or whatever is installed
elsewhere).
**Accepted cost:** 430 KB more in the install (first guessed at 300 KB); iPhone no longer shows
Apple's own serif.
**Found since:** the full Adobe font has real small caps and the Hungarian ő and ű; the trimmed
web copies have neither. The paper ships the full variable font cut down to Latin, renamed
"Paper Serif" as its licence (SIL OFL, reserved name "Source") requires of a modified copy:
430 KB for roman and italic
together, with ✓ added for D13.

## D10 · Voice of the page
**Chosen:** all serif. Section labels in small caps, leads in the same serif at a smaller size,
Settings and buttons included.
**Not chosen:** serif text with sans controls; keeping today's serif heads with sans leads.
**Accepted cost:** forms and buttons read less like an app.

## D11 · Grey
**Chosen:** one grey step for sources, dates and Earlier; everything read is ink.
**Not chosen:** ink only.

## D12 · Dark mode
**Chosen:** follow the system, pure inverse: paper-white ink on near-black, the icon inverted.
**Not chosen:** light only; system plus a manual switch.
**Not built yet:** the inverted icon. The home-screen icon is one picture and cannot follow the
theme; a browser-tab icon could.

## D13 · Right and wrong without colour
**Chosen:** the right answer turns solid ink with a ✓; the reader's wrong pick is struck through.
**Not chosen:** a line of words below the options; keeping green and red as the one exception.

## D14 · Marks in the text
**Chosen:** ¶ (highlight) or ? (question) in the margin beside the paragraph, and the marked
words underlined: solid for a highlight, dotted for a question. Links inside articles lose their
underline so they cannot be confused with marks.
**Found since:** the reader view extracts articles as text, so articles carry no links today;
the link rule only matters if links come back.
**Not chosen:** the glyph alone; inverse ink.

## D15 · Marks on the phone
**Chosen:** the glyph hangs in the 20 px side gutter.
**Not chosen:** leading the paragraph inline; underline only.
**Accepted cost:** close to the screen edge; a curved corner may clip it.

## Look calls made while building (to accept or reject)
These follow D4 and D10 to D15 but were not asked about one by one:
- buttons are ink-outlined pills, filled ink when pressed or kept;
- cards and games sit in a thin ink frame with small corners;
- the thread box on a piece is a 3 px ink bar on its left, with no fill;
- quoted passages (answers, article quotes) are italic ink behind a 2 px ink bar;
- the date links, Settings and Kept at the foot stay grey;
- Since you left opens with a 6 px ink bar and a ¶ before its label; other sections a 1.5 px rule;
- crossword squares that hold no letter are solid ink, as in print; in dark mode they stay the
  darkest part of the grid instead of inverting to white.

## D16 · What is encrypted, and how the morning run reads it
**Chosen:** `reads.jsonl` and `marks.jsonl` are encrypted. `context.json` exists only while the
morning run works: publish deletes it, and a copy left by a crash is deleted within hours.
`threads.jsonl` and `issues/` stay plain: they are news. `interests.md` stays plain as D1 chose,
though it is the most revealing file the reader keeps.
**Not chosen:** printing the context to Claude in parts so it never touches disk; encrypting
threads and issues too.
**Accepted cost:** for about ten minutes each morning a plain summary of the record is on disk.

## D17 · A lost key
**Chosen:** a recovery code, 24 characters, shown once on the computer; `paper restore <code>`
brings the record back on a new computer.
**Not chosen:** starting fresh; keeping the key beside the record.
**Accepted cost:** one more thing to keep; anyone with the code and the folder reads the record.

## D18 · How far the phone's certificate reaches
**Chosen:** limited to `.local` names and home-network addresses (10.x, 172.16–31.x, 192.168.x),
so a stolen copy cannot impersonate other sites, if the phone honours the limit.
**Not chosen:** no limit.
**To verify:** on a real iPhone and Android phone once built.

## D19 · Plain HTTP
**Chosen:** the computer keeps http://localhost. From the network, plain HTTP offers only the
certificate download and the way to HTTPS; the paper itself is served over HTTPS.
**Not chosen:** HTTPS for the computer too (a password prompt and a system trust change).
**Accepted cost:** the first certificate download is unencrypted; an active attacker on the
Wi-Fi at that moment could swap it.

## Calls made while building step 2

- HTTPS listens on 4748, one above the page's port; `PAPER_TLS_PORT` moves it.
- The QR code opens `http://<name>.local:4747/start` with the pairing key in the fragment, which
  never reaches the server over plain HTTP. The page's last link carries it to
  `https://…:4748/pair`, which pairs as before.
- An unpaired phone that reaches HTTPS sees the six-digit code page, as it did over HTTP.
- The recovery code shows at the top of Settings on the computer until "I've saved it" is
  pressed; never on a phone.
- In tests, `PAPER_RECOVERY_CODE` stands in for the keychain, so no test writes to it.

**Consequences to know:**
- A phone paired before this change has its home-screen icon at the plain-HTTP address, which
  now sends it to /start. It has to go through /start once and be added to the home screen again.
- I think, not verified: a keychain item made by `/usr/bin/security` is read by it again without
  a prompt, so the unattended morning run is not stopped. To check on the first real morning run.

## D20 · Windows
**Chosen:** needs Git for Windows. Setup checks for it and says where to get it; one installer
and one command form for the skills, as on Mac and Linux.
**Not chosen:** a PowerShell twin of the installer and the skills; WSL only (the phone cannot
reach a WSL 2 server without port forwarding).
**Accepted cost:** one more install for a Windows reader; hooks have reported bugs when WSL's
bash is picked over Git Bash.

## D21 · Linux
**Chosen:** Ubuntu and Debian with the Claude desktop app (beta), whose scheduled tasks run the
morning issue as on Mac and Windows.
**Not chosen:** any Linux through a systemd timer running `claude -p`; both.
**Accepted cost:** other distributions are left out, and the app is a beta.

## D22 · No keyring on Linux
**Chosen:** refuse and say why: install or unlock a keyring, or set `PAPER_RECOVERY_CODE`.
**Not chosen:** the key in a private file beside the record (encrypted in name only); asking.
**Accepted cost:** a stop at setup on unusual machines.

## D23 · Knowing it works elsewhere
**Chosen:** a GitHub Actions matrix (Ubuntu, Windows, macOS) runs the tests and the installer.
**Not chosen:** a real machine first; mocked tests only.
**Accepted cost:** it runs only when pushed; the phone, keyring and scheduling still need a real
machine.

## D24 · The phone's address
**Chosen:** the QR code keeps the `.local` name; Settings also shows the numeric address, for a
phone that cannot find the name (Android 11 and older, Windows machines that block it), which
then pairs with the six digits.
**Not chosen:** the numeric address in the QR code (a new address from the router breaks the
home-screen icon); `.local` only.
**Accepted cost:** one more line in Settings.

## Calls made while building step 3

- One installer, `scripts/install.sh`, for all three: it picks the uv and Node builds by system,
  checks each against its pinned checksum, unpacks Windows zips with PowerShell, and copies the
  plugin with tar (Git Bash has no rsync), keeping the engine's record across the copy.
- Windows always gets the x64 build: the encryption library has no Windows ARM wheel, and x64
  runs emulated on ARM.
- From login: launchd on macOS (as before), a systemd user unit on Linux, and an entry in the
  user's startup apps on Windows (the HKCU Run key, which needs no administrator, unlike a logon
  task). The Windows server runs windowless and logs to `serve.log`.
- On Windows a running program's files are locked, so the installer stops the server before it
  replaces the tools and starts it again after, through `paper install --stop` and `--again`.
- Every entry point runs Python in UTF-8 mode, or Windows reads and prints ő and ű in its old
  code page.
- `.gitattributes` keeps line endings LF, or Git for Windows checks the scripts out with CRLF and
  bash refuses them.

**Unverified:**
- CI (D23) passes on Ubuntu, Windows and macOS: the installer, the 78 tests, a new home, the
  keyring (a clear refusal on Ubuntu, Credential Manager on Windows), and the server over HTTP
  and HTTPS. Its first runs found two bugs: the startup-apps key is absent on a new Windows
  account, and a long computer name overflowed the certificate's 64-character common name.
- The session-start hook on Windows: Claude may hand it a backslash path, or WSL's bash instead
  of Git Bash. Neither the CI nor this Mac can check it. A failing hook does not block the
  session, and setup runs the installer itself, so the cost is a missed update, not a broken paper.
- Whether Windows shows the firewall prompt for a server started windowless from login, or only
  for one started from a visible window.
- Whether GNOME Keyring is unlocked when the systemd unit starts at login. If it is not, the
  pages say the record is locked until it is, and nothing is written.
- Settings now shows two plain addresses, the `.local` name and the number, where it showed the
  HTTPS one: a phone types either and reaches /start.
